# spec/vectors — A2A Wire v2.0 test vectors

English | [中文](README.zh.md)

The machine-readable conformance appendix. Every file is generated by `a2a/vectors_test.go` from **fixed seeds**, and the everyday `go test ./...` compares the current Go implementation's output with these files value by value — if either the files or the code change without the other, the test goes red immediately.

## Fixed inputs

| Identity | Ed25519 seed (32 B hex) | X25519 private scalar (32 B hex) | Fingerprint |
|---|---|---|---|
| **A** (sender / payer / card owner) | `01…01` (32 × 0x01) | `a1…a1` | `NHUPmL1Z_PyUbaRaqr6TOw` |
| **B** (receiver / payee) | `02…02` | `b2…b2` | `ajgD1fBZkCocba-8m6Rykg` |

Fixed timestamp `2026-08-22T01:02:03.123456789Z`; relay list `["https://relay.example.org","https://relay2.example.org"]`.

Rebuilding the keys: Ed25519 private key = `NewKeyFromSeed(seed)` (standard RFC 8032 derivation); X25519 private key = the 32 bytes used as the scalar as-is (clamping happens inside X25519).

## Files

| File | What it asserts | Spec section |
|---|---|---|
| `identity.json` | `ed_pub / ed_priv(64B) / x_pub / x_priv` base64 of both identities and their **fingerprints** | §2 |
| `card.json` | A's card JSON, the exact `signing_bytes` string, `sig`, the `soulmirror://card?…` URI, fingerprint; `ParseCard(uri)` round-trips | §3 |
| `request.json` | Signing strings `a2a-req-v2\n…` and signature values for `GET /mail` and `POST /mail/ack` (ts is fixed and long past the 5-minute window, so only the signature is checked, not the window) | §6 |
| `settle.json` | The `settle-v1\n…` signing string and the payer's signature | §9 |
| `dir-unpublish.json` | The `directory-unpublish:<fp>` signing string and signature | §8.2 |
| `profile.json` | Capability-card JSON after `PublicCopy`, **`signing_bytes` (exact Go encoding/json bytes, including the `&`/`<` escapes)**, `sig` | §8.3 |
| `convid.json` | The ordering rule of `ConvID` | §4.4 |
| `envelope.json` | The inner `message` A→B, `plaintext_json` (exact JSON bytes), **one fixed ciphertext** `envelope.cipher`, the outer signing string and `sig`, `from_xpub` | §4 |
| `chunk.json` | `MaxArtifactBytes` / `ChunkRawBytes` / threshold table / sample sha256 / `DeliveryZipName` / `SanitizeID` / `StripControlMarkers` | §5 §10 |

## How a third-party implementation uses them

1. **Deterministic parts** (identity / card / request / settle / dir-unpublish / profile / convid / chunk): run your implementation on the same inputs; **the output must be byte-for-byte identical**. Ed25519 signatures are deterministic, so even `sig` must match; a mismatch means your signing-string concatenation, encoding or JSON serialization differs — compare the `signing_bytes` field first, it is the raw bytes (a UTF-8 string) that get signed.
2. **Envelope**:
   - Decrypt: derive the key per §4.3 from B's `x_priv` + A's `x_pub` (or `envelope.from_xpub`); `Open(envelope.cipher)` must yield `plaintext_json` (JSON-semantic equality is enough; byte equality shows your serialization matches Go's).
   - Verify: `envelope.sig` over `envelope_signing_bytes` must verify under `envelope.from`; your own reconstruction of `"a2a-envelope-v2\n"+to+"\n"+ts(UTC RFC3339Nano)+"\n"+cipher` must equal `envelope_signing_bytes`.
   - Encrypt: the ciphertext you `Seal` (random nonce, so it can never equal the file) must be `Open`able by the Go implementation — the simplest way is a tiny Go test calling `a2a.Open`, or run this repository's relay + SoulMirror for a real exchange.
3. **Time windows / rate limits / long polling** and other clock-dependent behaviour are not in the vectors; self-test them against the spec.

## Regenerating (only on a deliberate protocol change)

```sh
A2A_WRITE_VECTORS=1 go test ./a2a/ -run TestVectors
```

The resulting diff must be reviewed in the same PR as the textual change to `spec/a2a-wire-spec.md`; vectors changing without the spec text (or the reverse) is not accepted.
